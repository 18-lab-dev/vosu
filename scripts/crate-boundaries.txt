# Interim edges (section 2 "Allowed workspace dependencies" notes, kept only
# until the named milestone):
# - vosu-osu-reader -> vosu-sys: interim until M5, DC (re-dated from the
#   original "until M1" by the A1b amendment: the 1.x readers keep reading
#   `ProcessMemory`/`MemoryError`/`ReadStatus`/`ReadRequest`/scanner
#   `Pattern` directly through all of M1, section 2 table, `vosu-osu-reader`
#   row). M5's brokered-reads boundary is where this edge is removed: a
#   plugin may run out of process from M5 on, so the reader must move onto
#   `vosu-plugin-api`/`PlanMemory` instead of touching `vosu-sys` directly.
# - vosu-osu-state -> vosu-sys: same reason and same M5 re-dating,
#   undocumented in the section 2 row for `vosu-osu-state` but required
#   today for the same ProcessMemory read types (`MemoryRead`, `ReadStatus`,
#   `MemoryError`) the reducer reads through; removed alongside the
#   vosu-osu-reader edge above at M5.
# - vosu-osu-reader -> vosu-net: F7, DD/R5. The lazer offset generator
#   moved from the root crate into `vosu-osu-reader` and still needs
#   `vosu_net::{ZipLimits, extract_zip_atomic}` for hardened extraction of
#   its embedded bundle; not interim, unlike the vosu-sys edges above.
# - vosu-osu -> vosu-surface: interim bridge B1 (P1, plan D3/plan:447-452),
#   until M4a. The root installs the process-wide `LegacySink` slot;
#   `vosu-osu` needs this edge only to call
#   `vosu_surface::bridge_b1::current()` and reach it, because the ABI's
#   `create(host, init)` has no Rust-level parameter to thread a
#   per-instance hook through instead (`crates/vosu-surface/src/lib.rs`
#   module doc); deleted alongside `vosu_surface::bridge_b1` itself at
#   M4a (`vosu-surface` otherwise continues on as the permanent D3
#   surface API).
