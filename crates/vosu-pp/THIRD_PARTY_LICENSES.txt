vosu-pp native live calculator
====================================

Scope and provenance
--------------------

The production calculator is implemented in Rust in `crates/vosu-pp/src`.
The replacement was requested and reported as clean-room, but recovered
authoring records show reads of the former Rust and LGPL reference during
that rewrite. This notice does not certify separation or implementation
independence. The source map records permissive calculation authorities and
observable compatibility requirements, not a complete implementation-origin
determination. See `docs/provenance-audit.md`. The module layout is:

- `src/lib.rs` and `src/model.rs`: public facade and wire models.
- `src/beatmap.rs`, `src/beatmap/random.rs`, and `src/mods.rs`: parsing, conversion,
  deterministic random-map transforms, mod decoding, and playable-map lifecycle.
- `src/data.rs` and `src/difficulty.rs`: difficulty and strain projections.
- `src/performance.rs`: full and retained-attribute performance calculation.
- `src/gradual.rs`: prefix calculation, skipping, rewind, score, and performance.
- `rosu-pp-api/src`: an in-tree source fork of MIT `rosu-pp` 4.0.1,
  forward-ported to the pinned MIT osu! revision below. Catch conversion
  retains osu!stable legacy slider approximation and timestamp/progress
  semantics in `catch/object/juice_stream.rs`. The retained mania closest-hitresult
  tests live in `mania/performance/hitresult_generator/closest/tests.rs`; this
  module extraction preserves the upstream test bodies and algorithm unchanged.
  Local API maintenance in `mania/performance/gradual.rs` clamps performance
  skips to the final object while preserving strict difficulty-iterator bounds;
  `osu/performance/gradual.rs` uses a non-consuming skip in its exhaustion
  example. `catch/object/banana_shower.rs` also has local security guards:
  stop generation when f32 timestamp addition cannot advance, and cap each
  object's generated bananas at 100,000. These local corrections preserve
  ordinary spacing/count semantics and do not change pinned upstream revisions
  or calculator evidence. Two local compatibility additions are not upstream
  rosu-pp behavior: the mode `difficulty/gradual.rs` files step once per source
  hit object, processing the difficulty objects whose base object has ended;
  and `osu/difficulty/skills/{aim,speed,reading}.rs` keep a strain-graph
  projection of per-object difficulties in fixed 400 ms sections with 0.15
  per-second decay. Both are written in rosu-pp's gradual and skill structure;
  the projection follows ppy/osu `StrainSkill.cs` section handling and the
  `Flashlight.cs` initial-strain form. The observable step and graph values
  are compatibility behavior checked by black-box vectors.
- `rosu-map-api/src`: an in-tree source fork of MIT `rosu-map` 0.2.1,
  with ppy-aligned circular-arc tolerance, degeneracy epsilon,
  `Math.Acos` float-argument promotion, f64-promoted vector-length
  calculation, and the legacy offset curve API used by catch conversion.
- `src/scoring.rs`: accuracy, score simulation, and total score.
- `src/hit_windows.rs`: temporal hit windows; Catch's map windows report every judgement as zero, separately from spatial catcher width.
- `src/score_multiplier.rs`: ruleset score-multiplier calculations.
- `src/source_map.rs`: machine-readable declared behavior attribution.

The source map catalogs the permissive upstream snapshots below and their
corresponding Rust paths. Source correspondence does not establish that every
adapter was independently implemented.

The historical manifest (`tools/oracle/calculator-diff-manifest.json`) and
former `vosu-lazer-pp` notice identify tosuapp/lazer-calculator
`9a22c4c74f8e584fa64133a79a204dd045646bac` (LGPL-3.0-only). Its simulator and
accuracy routines include MIT osu-tools material, and the retained catch
equation traces to MIT rosu-pp and osu! sources. However, the rewrite agents
also read the former Rust and LGPL C# and received wrapper-derived details.
The implementation origins of signed-score adapters, data/strain projections,
gradual boundaries and compatibility arrangements remain under review.
The reference is outside the production build graph and is retained for
historical comparison and black-box tests; that boundary does not establish
source independence. No legal clearance or clean-room certification is made.

Historical parity evidence (not a production source)
------------------------------------------------------

`tools/oracle/reference/lazer-calculator` is retained as historical parity
evidence only. It records former tosuapp/lazer-calculator behavior for
comparison and audit history; it is **not** the current calculator fixture's
oracle, a production build input, crate dependency, or runtime dependency.
The current generated oracle fixture targets `osu-pp-calculator` 0.6.1 as
pinned in `tools/oracle/oracle-lock.json`. The production workspace does not
include or compile the historical directory. This build boundary does not
by itself prove source independence from the former wrapper.
