# Source map

Start with the owning boundary below rather than searching the whole tree. The [architecture overview](overview.md) explains how these areas connect at runtime.

| Area | Owner | Use it for |
|---|---|---|
| Startup and lifecycle | `src/runtime/` | CLI decisions, composition, workers, shutdown and reload; loading production `vosu.osu` from `plugins::BUNDLED` and debug `--plugin <dir>` plugins through core (`dev_plugins.rs`); required osu! plugin load/create or missing discovery fails composition. Core discovery and the Windows foreground poller stop before plugins, then B1 is joined. |
| Core services | `crates/vosu-core/` | Config, logging, diagnostics report generation, self-update, desktop integration (session tray, executable ownership policy, opt-in Linux systemd user login service), startup decisions/guards, and the plugin host (`crates/vosu-core/src/plugin/`: the `BUNDLED`/`dlopen` registry, instance lifecycle, dispatch, host vtable `send` routing, process matching (`matcher.rs`, §6.1), session lifecycle/the Focus rule (`session.rs`/`focus.rs`, §6.2), the generic discovery service (`discovery.rs`, §6.1, M1 §4 phase d2b: one dedicated thread, a pluggable `ProcessSource` seam — Linux eBPF/CN_PROC/polling, Windows polling with an executable-name pre-filter against the enabled plugin set's `process_names`, and a Windows foreground-window poller), memory read plans and signature scans routed through `PluginHost` (`host/read_plans.rs`/`host/scans.rs`, §6.3/§6.4, sharing one per-session cached process handle), and the M1 host services settings/logging/timers (§6.9-§6.11, built on the core `config`/`logging` modules)), and the M2 state bus's schema registry (`src/state/schema/`: embedded `docs/v2/schemas/*.schema.json`, SDK-compiled namespace metadata and versioned registration with explicit trusted-bundled provenance for `vosu.osu`'s `/internal` carve-out) — `docs/v2/plugin-abi.md` §1, §2, §4, §5, §6.1, §6.2, §6.3, §6.4, §7.1) |
| State commit path | `crates/vosu-core/src/state/` (`grant.rs`, `store.rs`, `commit.rs`, `client.rs`) | Core-owned immutable per-session namespace documents and client facts, manifest-derived publication authority, whole-batch validation before copy-on-write mutation, serialized ArcSwap publication and latest-only revision watches. Commits are bounded to 4 MiB/namespace and 65,536 keys/session; rejection changes neither values nor revision. Session lifecycle error classification stays in the plugin host. |
| State reference publication | `crates/vosu-core/src/state/reference.rs` | The one-way `state -> resources` edge supplies authenticated publish-time resource/tree projections and fixed MIME types. Session commit locks precede the shared reference registry lock; prepared membership commits atomically with state, subtree replacement and detach release bindings, and revision notification runs after unlock. Production injects a persisted-secret `ReferenceStore`; no file opening or plugin resolution runs on publication. |
| State subscriptions | `crates/vosu-core/src/state/{demand,subscriptions,update}.rs` | Schema-lane union with play/pause gating, wholesale per-session subscriptions, projected change detection, exact-CBOR frame splitting and latest-per-key pending updates. Change detection compares float bits recursively (unchanged NaNs do not emit updates), reuses the current projection for delivery, and sorts/deduplicates complete demand. Limits: 256 selectors/subscription, 256 subscriptions/subscriber, 1,024 subscriptions total and 1,024 distinct demand selectors/session; pending updates retain at most 256 frame-bounded entries. Replacement must clear pending keys before its baseline. Split/merge return errors without dropping pending data when a cap cannot hold even the error envelope. |
| State host wiring | `crates/vosu-core/src/plugin/host/{state,state_delivery}.rs`, `crates/vosu-core/src/state/runtime.rs` | Manifest-granted publication, client facts and lifecycle-owned documents; latest-only state/demand slots drained on existing instance workers with weak 10 ms queue-full retries. Split updates stay serial under concurrent dispatch. Session replay starts at identify and strips non-owner process facts; unseen attach/detach pairs cancel. A 4,096-undelivered-entry lifecycle backstop sends `DETACHED(lost)` for announced sessions and unsubscribes; resubscription replays the current list. Detach closes the store and merges final subscriber selections before its terminal event. Overflow removes only non-owned lifecycle-session subscriptions. Host lock order: focus → state_serial → instances → sessions → registry → subscriptions. |
| Resource host wiring | `crates/vosu-core/src/plugin/host/{resources,resource_requests}.rs` | Retained declared-root capabilities with revocable epochs and session-over-plugin scope selection; 64 pending lazy operations per instance, host-monotonic correlation IDs, typed replies, bounded deadlines and cancellation on future drop, root replacement, detach or shutdown. Opens and dispatch run outside resource locks. `PluginHost::new_with_resources` injects composition's shared `ReferenceStore`; `is_persistent` distinguishes loaded persisted secrets from ephemeral test defaults. |
| Resource HTTP authority | `crates/vosu-core/src/plugin/host/resources.rs`, `src/server/api_v1/{resources,trees,resource_headers}.rs` | The `plugin -> resources` edge authenticates current registry membership against loaded plugins and selects a live binding plus manifest MIME families. The HTTP adapter holds weak host ownership, keeps legacy dispatch unchanged, streams bounded chunks, applies validators/ranges/security headers, and redirects only from public state references. Production composition supplies a five-second per-operation provider deadline, not a whole-download deadline. |
| Reserved terminal delivery | `crates/vosu-core/src/plugin/{outbox,dispatch_queue}.rs` | Per-instance 128-slot reservations guarantee FIFO terminal dispatch even when the ordinary dispatch queue is full. A reserved runner wakes existing workers without polling; delivery receivers complete only after the callback returns. Instance teardown drops undelivered messages before freeing plugin context. |
| Lazy byte sources | `crates/vosu-core/src/resource_io/{resolve,stream}.rs`, `crates/vosu-core/src/plugin/resource_lease.rs` | The acyclic `resource_io -> plugin/resources` composition connects pure identity records to host-owned byte leases. Successful file opens alone enter the 128-entry cache; no byte snapshots are created. File reads revalidate the opened handle's disk identity before and after bounded reads (Unix device/inode/size/mtime/ctime; Windows volume/file-id/size/LastWriteTime/ChangeTime). Mutation yields typed Gone; missing files yield NotFound. HEAD validators use the same identity and explicit handle verification without byte hashing. Stream reads are chunk-bounded, offset-checked, and close through reserved terminal slots on drop, EOF, error, timeout or revocation; no stream resolution is reused. Eviction/retirement invalidates cached capabilities and matching active leases. |
| Tree indexes and canonical lookup | `crates/vosu-core/src/resources/{tree,index,path,media}.rs`, `crates/vosu-core/src/resource_io/tree.rs` | Pure index validation rejects noncanonical portable paths and exact duplicates, caps indexes at 16,384 entries and the 1 MiB ABI frame, preserves truthful provider truncation and omitted unknown hashes, and shares publication's MIME allowlist. `TreeResolver` re-lists before each request, reuses equal validated representations in a 16-index cache, and requires exact canonical `entry_path` membership before opening or accepting a stream. Request aliases remain plugin-owned; types come only from indexed paths. Provider `gone` remains typed for HTTP 410 without retaining private error messages. |
| Action invocation | `crates/vosu-core/src/actions/{registry,invocation}.rs`, `crates/vosu-core/src/plugin/host/{actions,action_delivery}.rs` | Exact manifest action lookup, compiled argument/result schemas, live tool authority checks, fixed session ownership and a shared 30-second invocation policy. HTTP jobs use a job sink; ABI relays remap host ids and retain each of 64 caller slots through actual terminal callback completion using the reserved outbox. No action callbacks run under action registry locks. |
| Shared action contracts | `crates/vosu-core/src/actions/`, `crates/vosu-core/src/action_schema/`, `crates/vosu-core/src/identity.rs` | The pure action domain uses the bounded schema compiler and neutral instance id. `InvocationHost` inverts runtime dispatch: executors and job cancellation retain only a weak host trait object; the plugin host implements it without a cyclic module dependency. `plugin::PluginInstanceId` remains the public plugin API re-export of that neutral identity. |
| Bundled state reads | `crates/vosu-surface/src/state.rs`, `crates/vosu-core/src/{state,plugin/host}/surface.rs` | Permanent D3 reads authorize loaded bundled readers through their manifests, use the ABI subscription/demand registry and D2 projector, and rebind focused selections with full baselines. ## Cleanup module boundaries

Maintained code files stay at or below 1,000 physical lines, including tests,
benchmarks, dashboard styles/scripts, and maintainer tools. Lockfiles and pinned
JSON/beatmap evidence are data, not source-size exceptions or splitting targets.
`python scripts/check-file-length.py` enforces this in CI. Files that were already
over the limit are listed in `scripts/file-length-baseline.txt`; an entry may
only shrink or be removed (`--update` refuses to raise or add one).

Dependencies between each crate's own top-level modules are recorded per
crate in `scripts/module-boundaries/<crate>.txt` and checked by
`python scripts/check-module-boundaries.py`; the allowed dependency edges
between workspace crates are recorded in `scripts/crate-boundaries.txt` and
checked by `python scripts/check-crate-boundaries.py` against `cargo
metadata`. Adding either kind of edge is a deliberate change: record it in
the same change that explains the new dependency here or in the
[architecture overview](overview.md). `memory`, `calculation`, and `state`
no longer cycle: the JS-compatible rounding/mods/grade helpers
(`crates/vosu-osu-model/src/root/{helpers,mods,scores}.rs`) and the state reducer's
calculation backend (`crates/vosu-osu-state/src/state_backend.rs`) live under
`vosu-osu-model` and `vosu-osu-state` respectively, not `vosu-osu-calc`, so readers
depend only on the model and `vosu-osu-state -> vosu-osu-calc` (a `scripts/crate-boundaries.txt`
crate edge, not a `scripts/module-boundaries/<crate>.txt` module edge, since `state` is no longer a top-level
module of the `vosu` package) is the only edge left.
`server` and `tools` no longer cycle either: `server::routes::RouteExtension`
(implemented by `tools::ToolHost`) covers the reserved `/tools` overlay prefix
and the dashboard tool management routes, and `server::ids::valid_id`
(re-exported as `tools::manifest::valid_id`) is the shared identifier check,
so `tools -> server` is the only edge left.

- `crates/vosu-osu-reader/src/offset_generator.rs` depends on its own crate's
  `assets` (the embedded generator bundle and offsets template) and `memory`
  (`lazer_loader`'s `OffsetGenerator` trait it implements, `lazer_version`'s
  version check) module edges, recorded in
  `scripts/module-boundaries/vosu-osu-reader.txt`; no other module reaches it.
- `crates/vosu-osu-state/src/bundle/publication.rs` owns immutable snapshot materialization and
  regular/precise Arc reuse; `reducer.rs` owns state transitions.
- `crates/vosu-osu-state/src/bundle/resources.rs` exposes explicit cold resource facts,
  retaining the reader's shared lazer set and skin indexes. Accepted selections advance
  a generation; asynchronous results must pass `ColdResourceFacts::is_current` before
  publication (including instance/reset and root/skin checks). No capture tick constructs
  this descriptor, reads more client memory, or allocates/copies a set index. These are
  internal source facts, not filesystem authority or added public state paths.
- `crates/vosu-osu/src/actions/import/` owns bounded local `.osz` snapshots,
  reusing `vosu-net` counter ZIP count/path/type preflight protections. It prepares
  same-filesystem stable no-clobber stages and selected-context lazer handoffs,
  never writable action destinations or database writes. The dispatch owner
  bounds blocking-worker admission, cancels/joins preparation, retains the
  selected session generation and awaits/reaps handoffs through shutdown.
- `crates/vosu-pp/src/beatmap/random.rs` owns deterministic random-map transforms.
  Calculator tests group gradual, hit-window, mod, stateful-oracle, and scoring
  contracts under their existing integration-test entrypoints.
- Counter settings, v2 hit windows, pause transitions, and updater handoff tests
  live in child modules of their existing suites, sharing the existing fixtures.
- `examples/support/process_event_metrics.rs` owns resource and latency reporting,
  separate from the benchmark's process lifecycle orchestration.
- `tools/oracle/calculator/` separates binding helpers, provenance/coverage
  validation, replay contracts, and pinned multiplier/conversion evidence.
- `tools/input-validation/capture.py` owns bounded WebSocket transport and capture
  accounting; `input_validation.py` owns input playback and live scheduling.
  Both use `validation_error.py` for the shared error contract.
- Offset-generator partial classes separate runtime validation, target ownership,
  and generation; offset-target files separate assembly loading, schema, and CLI
  parsing. Their `bin/` and `obj/` trees are reproducible ignored build output.
  The prepared platform ZIP and checksum are release build inputs, while package
  locks remain maintained inputs.
- The dashboard loads `homepage.js` as an ES module, after the classic
  `theme-init.js`, which applies the stored colour mode before first paint. `tokens.css` is the single
  source of design tokens and `@font-face` rules (custom properties and font
  rules only, with absolute `/assets/` URLs); `system.css` holds the shared
  `v-` components. Tool UIs receive both, concatenated, as
  `/tools/_host/v1/theme.css`, and `design.html` is the reference page at
  `/tools/_host/v1/design` ([design guide](../tools/design.md)). `homepage-settings.js` owns the overlay and tool
  settings editor; `dashboard-tools.js` owns the Tools page and loads only
  there; `homepage-controls.css` follows the base stylesheet and preserves
  settings/dialog/responsive cascade order.

## Workspace boundaries

`Cargo.toml` defines one workspace with the production `vosu` package, the `vosu-sys` crate (native process/platform/process-event boundary, M0 crate split), the `vosu-net` crate (hardened outbound HTTPS streaming and archive extraction, M0 crate split), the `vosu-osu-model` crate (osu! value types and calculation root helpers, M0 crate split), the `vosu-osu-calc` crate (beatmap parsing, progressive state, and legacy/live calculation engines over `vosu-pp`, M0 crate split), the `vosu-osu-reader` crate (stable/lazer memory readers and offsets, the pointer-width managed-heap read layer, and osu!-specific discovery inputs, M0 crate split), the `vosu-osu-state` crate (reducer, capture scheduling, and gameplay state, plus the state calculation backend, M0 crate split), the `vosu-pp` facade plus its `rosu-map-api` and `rosu-pp-api` members, the integration-only `vosu-test-harness`, the dependency-isolated `vosu-release-smoke` package, and the dev-only `vosu-proptest` package (`vosu_proptest_config()`, shared by every `prop_*` test). The smoke package launches an external packaged executable and does not depend on the daemon crate. Release profiles retain thin LTO, one codegen unit, stripped symbols, and abort-on-panic; `test-harness` is rejected by `build.rs` in release builds.
