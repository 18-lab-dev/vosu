# Source map

Start with the owning boundary below rather than searching the whole tree. The [architecture overview](overview.md) explains how these areas connect at runtime.

| Area | Owner | Use it for |
|---|---|---|
| Startup and lifecycle | `src/runtime/` | CLI composition, explicit required game/adapter registration (`dev_plugins.rs`), shared schema providers, listeners/hubs, OS shutdown signals (`signals.rs`) and joined adapter/plugin shutdown that collects every cleanup error instead of stopping at the first. No root snapshot/control fallback. `dev_plugins.rs` also loads `--plugin` packages under catalog-v2.md A5.5's build policy and installs `ProcessHostLauncher` only inside the approval gate (the `runtime -> plugin_host` edge is the launcher's `BUILD_IDENTITY`); `plugin_management.rs` serves the dashboard's `/api/plugins` approval and management routes and `GET`/`POST /api/plugins/<id>/settings` (A7.1 `PluginSettings`); `overlay_root.rs`'s `RuntimeSettingsStorage` routes `vosu.osu` to bridge B2, `vosu.overlayhost` to the overlay-root seed and every other plugin id to core's `PluginSettingsStore`. |
| Background startup and log viewer | `build_support/windows_manifest.rs`, `crates/vosu-sys/src/platform/console.rs`, `src/runtime/cli.rs`, `crates/vosu-core/src/logging/`, `crates/vosu-core/src/desktop/tray_logs.rs` | One console-subsystem executable: detached Windows graphical launches, inherited terminal semantics, file tail/follow with rotation, and tray-launched visible terminals (ADR 0024). |
| Core services | `crates/vosu-core/` | Config, logging, diagnostics report generation, self-update, desktop integration (session tray, executable ownership policy, opt-in Linux systemd user login service), startup decisions/guards, and the plugin host (`crates/vosu-core/src/plugin/`: the `BUNDLED`/`dlopen` registry, instance lifecycle, dispatch, host vtable `send` routing, process matching (`matcher.rs`, §6.1), session lifecycle/the Focus rule (`session.rs`/`focus.rs`, §6.2), the generic discovery service (`discovery.rs`, §6.1, M1 §4 phase d2b: one dedicated thread, a pluggable `ProcessSource` seam — Linux eBPF/CN_PROC/polling, Windows polling with an executable-name pre-filter against the enabled plugin set's `process_names`, and a Windows foreground-window poller), memory read plans and signature scans routed through `PluginHost` (`host/read_plans.rs`/`host/scans.rs`, §6.3/§6.4, sharing one per-session cached process handle), and the M1 host services settings/logging/timers (§6.9-§6.11, built on the core `config`/`logging` modules; `settings/store.rs` is M7's per-plugin `PluginSettingsStore`, `<config>/plugins/settings.json`, holding each plugin's overrides of its schema defaults, and `PluginSettingsService` builds the dashboard's write-only view and validated, whole-document `SETTINGS_CHANGED` writes)), and the M2 state bus's schema registry (`src/state/schema/`: embedded `docs/v2/schemas/*.schema.json`, SDK-compiled namespace metadata and versioned registration with explicit trusted-bundled provenance for `vosu.osu`'s `/internal` carve-out) — `docs/v2/plugin-abi.md` §1, §2, §4, §5, §6.1, §6.2, §6.3, §6.4, §7.1) |
| Plugin execution backends | `crates/vosu-core/src/plugin/{registry,execution,instance}.rs`, `crates/vosu-core/src/plugin/execution/`, `crates/vosu-core/src/plugin/host/{instances,instance_loss}.rs` | One package validation path (manifest, schemas, grants, action assets) with explicit bundled/development provenance, then one execution backend: local code (linked bundled vtable, or a debug development library mapped through the shared descriptor helper) or a `runtime = "process"` package whose confined library core never maps. Instances reuse the same dispatch queues, outbox and state delivery against a local vtable or a launcher-provided process endpoint; plugin → host ingress shares the in-process `send` validation. Without an installed launcher a process package is refused. Loss is reported once per instance and retired off the reporting thread: matcher unregistered, owned sessions detached `lost`, then the shutdown cleanup path. |
| Plugin-host child entry | `src/plugin_host.rs`, `src/main.rs`, `crates/vosu-core/src/plugin/process/{entry,control}.rs`, `crates/vosu-core/src/plugin/process/bootstrap.rs` and `bootstrap/{library,services}.rs` | `vosu plugin-host` (plugin-abi.md §7.6): `src/main.rs` dispatches it before `vosux`, any runtime or daemon service; `src/plugin_host.rs` holds the executable's build identity. `entry` checks the exact arguments and identity, arms parent death, adopts the endpoints and runs the Linux drop (or the Windows attach); `control` holds the `CREATE`/`READY`/`FAILED` codecs, startup stages and private exit statuses 70–76; `bootstrap` reads `CREATE`, loads the library through the object whose digest it verified, calls `create`, reports `READY`/`FAILED`, runs the controlled destroy, and serves the child's local `send` (acknowledged sends, waiters, ring reader, dispatch worker). |
| Plugin-host launcher | `crates/vosu-core/src/plugin/process/launcher.rs` and `launcher/{platform,supervision}.rs` | Core's `ProcessLauncher` (`ProcessHostLauncher`): spawns one child of this executable generation per instance through the Linux `HostSpawner` or Windows `windows_launch`, sends `CREATE`, enforces the 5-second startup deadline, and supervises the generation with one exit watcher (the only reaper) and one ring reader answering `STATUS`; reports one loss, and destroys with a 5-second grace before kill and reap. Production launches only through `ApprovalGate::launch_approved` with the approved digest; the digest-hashing `ProcessLauncher` impl exists only for tests and fixtures. |
| Process-plugin approval | `crates/vosu-core/src/plugin/approval.rs` | catalog-v2.md A5.5: the `plugins/approvals.json` store (fails closed when unreadable) and `ApprovalGate`, which every load and restart passes; it refuses with startup stage `approval` unless the current manifest and library digests, runtime and provenance match a record. |
| State commit path | `crates/vosu-core/src/state/` (`grant.rs`, `store.rs`, `commit.rs`, `client.rs`) | Core-owned immutable per-session namespace documents and client facts, manifest-derived publication authority, whole-batch validation before copy-on-write mutation, serialized ArcSwap publication and latest-only revision watches. Commits are bounded to 4 MiB/namespace and 65,536 keys/session; rejection changes neither values nor revision. Session lifecycle error classification stays in the plugin host. |
| State reference publication | `crates/vosu-core/src/state/reference.rs` | The one-way `state -> resources` edge supplies authenticated publish-time resource/tree projections and fixed MIME types. Session commit locks precede the shared reference registry lock; prepared membership commits atomically with state, subtree replacement and detach release bindings, and revision notification runs after unlock. Production injects a persisted-secret `ReferenceStore`; no file opening or plugin resolution runs on publication. |
| State subscriptions | `crates/vosu-core/src/state/{demand,subscriptions,update}.rs` | Schema-lane union with play/pause gating, wholesale per-session subscriptions, projected change detection, exact-CBOR frame splitting and latest-per-key pending updates. Change detection compares float bits recursively (unchanged NaNs do not emit updates), reuses the current projection for delivery, and sorts/deduplicates complete demand. Limits: 256 selectors/subscription, 256 subscriptions/subscriber, 1,024 subscriptions total and 1,024 distinct demand selectors/session; pending updates retain at most 256 frame-bounded entries. Replacement must clear pending keys before its baseline. Split/merge return errors without dropping pending data when a cap cannot hold even the error envelope. |
| State host wiring | `crates/vosu-core/src/plugin/host/{state,state_delivery}.rs`, `crates/vosu-core/src/state/runtime.rs` | Manifest-granted publication, client facts and lifecycle-owned documents; latest-only state/demand slots drained on existing instance workers with weak 10 ms queue-full retries. Split updates stay serial under concurrent dispatch. Session replay starts at identify and strips non-owner process facts; unseen attach/detach pairs cancel. A 4,096-undelivered-entry lifecycle backstop sends `DETACHED(lost)` for announced sessions and unsubscribes; resubscription replays the current list. Detach closes the store and merges final subscriber selections before its terminal event. Overflow removes only non-owned lifecycle-session subscriptions. A non-owner holding an attached handle publishes plain values in its own namespace only and gets demand filtered to it; retirement clears that namespace after an exclusive guest-publication gate drains in-flight commits. Host lock order: focus → state_serial → instances → sessions → registry → subscriptions. |
| Resource host wiring | `crates/vosu-core/src/plugin/host/{resources,resource_requests}.rs` | Retained declared-root capabilities with revocable epochs and session-over-plugin scope selection; 64 pending lazy operations per instance, host-monotonic correlation IDs, typed replies, bounded deadlines and cancellation on future drop, root replacement, detach or shutdown. Opens and dispatch run outside resource locks. `PluginHost::new_with_resources` injects composition's shared `ReferenceStore`; `is_persistent` distinguishes loaded persisted secrets from ephemeral test defaults. |
| Resource HTTP authority | `crates/vosu-core/src/plugin/host/resources.rs`, `src/server/api_v1/{resources,trees,resource_headers}.rs` | The `plugin -> resources` edge authenticates current registry membership against loaded plugins and selects a live binding plus manifest MIME families. The API v1 HTTP adapter holds weak host ownership, streams bounded chunks, applies validators/ranges/security headers, and redirects only from public state references. Production composition supplies a five-second per-operation provider deadline, not a whole-download deadline. Legacy game routes independently use the bundled upstream surface provider's retained-root selections. |
| Reserved terminal delivery | `crates/vosu-core/src/plugin/{outbox,dispatch_queue}.rs` | Per-instance 128-slot reservations guarantee FIFO terminal dispatch even when the ordinary dispatch queue is full. A reserved runner wakes existing workers without polling; delivery receivers complete only after the callback returns. Instance teardown drops undelivered messages before freeing plugin context. Each instance's lifecycle lane admits one `SESSION_DETACHED` delivery per session past the ordinary bound, at the end of the ordinary FIFO, so a full queue never loses or reorders a detach. |
| Lazy byte sources | `crates/vosu-core/src/resource_io/{resolve,stream}.rs`, `crates/vosu-core/src/plugin/resource_lease.rs` | The acyclic `resource_io -> plugin/resources` composition connects pure identity records to host-owned byte leases. Successful file opens alone enter the 128-entry cache; no byte snapshots are created. File reads revalidate the opened handle's disk identity before and after bounded reads (Unix device/inode/size/mtime/ctime; Windows volume/file-id/size/LastWriteTime/ChangeTime). Mutation yields typed Gone; missing files yield NotFound. HEAD validators use the same identity and explicit handle verification without byte hashing. Stream reads are chunk-bounded, offset-checked, and close through reserved terminal slots on drop, EOF, error, timeout or revocation; no stream resolution is reused. Eviction/retirement invalidates cached capabilities and matching active leases. |
| Tree indexes and canonical lookup | `crates/vosu-core/src/resources/{tree,index,path,media}.rs`, `crates/vosu-core/src/resource_io/tree.rs` | Pure index validation rejects noncanonical portable paths and exact duplicates, caps indexes at 16,384 entries and the 1 MiB ABI frame, preserves truthful provider truncation and omitted unknown hashes, and shares publication's MIME allowlist. `TreeResolver` re-lists before each request, reuses equal validated representations in a 16-index cache, and requires exact canonical `entry_path` membership before opening or accepting a stream. Request aliases remain plugin-owned; types come only from indexed paths. Provider `gone` remains typed for HTTP 410 without retaining private error messages. |
| Action invocation | `crates/vosu-core/src/actions/{registry,invocation}.rs`, `crates/vosu-core/src/plugin/host/{actions,action_delivery}.rs` | Exact manifest action lookup, compiled argument/result schemas, live tool authority checks, fixed session ownership and a shared 30-second invocation policy. HTTP jobs use a job sink; ABI relays remap host ids and retain each of 64 caller slots through actual terminal callback completion using the reserved outbox. No action callbacks run under action registry locks. |
| Shared action contracts | `crates/vosu-core/src/actions/`, `crates/vosu-core/src/identity.rs` | The pure action domain uses the SDK's bounded action-schema compiler (`vosu_plugin_api::manifest::action_schema`, the one A3 profile check shared with `vosu-package-check`) and neutral instance id. `InvocationHost` inverts runtime dispatch: executors and job cancellation retain only a weak host trait object; the plugin host implements it without a cyclic module dependency. `plugin::PluginInstanceId` remains the public plugin API re-export of that neutral identity. |
| Job artifacts (AF.12) | `crates/vosu-core/src/actions/{artifacts.rs,jobs/artifact_jobs.rs}`, `crates/vosu-core/src/plugin/host/artifacts.rs`, `crates/vosu-core/src/resource_io/artifact.rs`, `src/server/api_v1/artifacts.rs`, `assets/server/tool-bridge.js` | Protected or sessionless outputs a `tool`/`cli` invocation declares (`ARTIFACT_DECLARE`/`DECLARED`/`OPEN`/`RELEASE`, plugin-abi §6.13) are cells owned by that one job: random ids, 4 per job and 256 live, released at once when the job ends other than `succeeded`, by a one-shot deadline at the end of retention, or when its launch session is invalidated. Opens reuse the request table under a sessionless lease owner (a stream lease or a file below a plugin-wide root); the plugin's release follows every lease's `STREAM_CLOSE`. `GET`/`HEAD /api/v1/jobs/{job}/artifacts/{artifact}` applies the job route's credential, one byte range and no-store attachment headers, rechecking authority on every chunk without buffering. The bridge's `vosu.artifacts`/`handle.artifacts()` read and download them with the launch session. |
| Bundled state reads | `crates/vosu-surface/src/state.rs`, `crates/vosu-core/src/{state,plugin/host}/surface.rs` and `plugin/host/surface/capture.rs` | Permanent D3 reads authorize loaded bundled readers through their manifests, use the ABI subscription/demand registry and D2 projector, and rebind focused selections with full baselines. Bound instance requesters capture one immutable cross-namespace image and identified roster, with independent foreground facts and per-namespace revisions. One-shot reads create no demand; subscriptions support atomic selector replacement. |
| Public API audience/session source | `crates/vosu-core/src/api/`, `crates/vosu-core/src/plugin/host/api.rs` | Non-owning `ApiStateSource` reads use `Audience::Api` without demand. Validated merged-document plans register distinct `SubscriberId::Api` demand with RAII cleanup; internal root expansion is bounded separately from the 256 public selectors. Latest-only watches carry full selected snapshots and terminal detach/shutdown state. Session-event snapshots are built once after a completed lifecycle/focus transition, including both focus flips, with no JSON serialization or clock reads on unobserved publications. |
| Plugin ABI v1 | `crates/vosu-plugin-api/` | `repr(C)` ABI v1 types mirroring `include/vosu_plugin.h` (constants, opcodes, flags, error codes, envelope, flat payload structs, host/plugin vtables), layout tests against `docs/v2/plugin-abi.md` §3, flat payload validation, CBOR codecs, and the `Plugin`/`ConcurrentPlugin` Rust SDK with the `cdylib` `export_plugin!` (`docs/v2/plugin-abi.md` §9). Published to crates.io (D11): no Cargo features, no workspace dependency, a crate README and license copies; `examples/vosu-package-check/` is the AF.10 publisher checker over the SDK's own validators. Header, packaging-schema and `prop_*` checks that need workspace files are the root `tests/sdk.rs` (`tests/sdk/`); `scripts/sdk-package.py verify` checks the packaged `.crate` outside the workspace |
| Workspace-only plugin glue | `crates/vosu-plugin-internal/` | `publish = false` (AF.9): `PlanMemory` synchronous reads and their zero-allocation `read_flat` (D5, D17); the dispatch glue that wraps the SDK's `dispatch` to claim a synchronous `READ_PLAN_RESULT` before the plugin sees it; `export_plugin!`'s bundled form (D13) and the intercepting `cdylib` form for the osu! process fixture; `read_plan_profile` opt-in per-thread SDK/core phase diagnostics outside the wire ABI |
| Unified package and namespace validation | `crates/vosu-plugin-api/src/{manifest,capability}.rs`, `manifest/{package,context,requirements,legacy_metadata}.rs`, `manifest/schema/` | Single pure plugin/tool/overlay parser, explicit host/registration context, shared semver/coverage predicates and D7 full-document extraction. Core retains schema lifetime/grants/demand; root tool and overlay adapters retain live authority and confined I/O. See the [consumer migration ledger](../testing/verification.md#consumer-migration-ledger). |
| Catalog v2 validation | `crates/vosu-plugin-api/src/catalog/` | Pure strict catalog parser, package-backed mirror comparison and explicit source/registration/host/target checks, reusing unified manifest validation and schema extraction. No fetching, trust inference, install mutation or local package-size policy. |
| Catalog credentials | `crates/vosu-core/src/catalog/credentials/` | Channel-config-root exact-source write-only secrets; 256 KiB/32-entry persistence and bounded inputs, redacted presence/errors, immutable core-only fetch leases and durable mutation generations. Same-directory 0600 Unix tempfiles / inherited Windows directory ACLs use the existing `vosu-core -> vosu-sys` platform replacement edge; no new intra-core module edge. S0 owns source-removal roll-forward journal/recovery and invokes serialized credential purge/membership reconciliation before exposing source services. Malformed stores remain disabled and untouched until explicit validated full replacement. |
| Catalog game offers | `crates/vosu-core/src/catalog/game/`, `crates/vosu-core/src/plugin/host/observer.rs` | `GameOffers` observes the existing discovery service through the generic `DiscoveryObserver` seam (re-offer generation; no poller). Observer pre-filter interest is names-only within a separate 64-name budget and the free Linux kernel-table capacity: catalog content never widens the filter or displaces installed names, so path/command-line-only entries detect only already-observed processes. Runtime `CompiledMatcher` over enabled, supported, uninstalled SDK-validated catalog game entries, never registered, so catalog overlaps stay allowed; offers for processes an installed plugin already matched are flagged `installed_match`. 64 offers keyed by source/id/pid/start time, cleared on exit, PID reuse and source/installed publication; redacted view; acceptance builds a normal requested P0 plan for the exact source. Root composition pending. |
| Catalog native trust policy | `crates/vosu-core/src/catalog/{trust,approvals}.rs` | Exact current-source tiers, artifact-bound process approval, source-generation plan checks and explicit stop/pending-restart effects. W4 owns serialized installed-record publication and real M5 execution; dashboard provenance/CSRF and the per-grant warning remain H0-owned. |
| Catalog graph resolution | `crates/vosu-core/src/catalog/resolver/` | Immutable SDK-validated candidates and installed manifests; exact-source ranking, pinned installed roots, bounded whole-plugin backtracking and dependency-first edges. Built-ins come from the actual schema registry and compiled bundled manifests; optional closure never selects providers. No network, filesystem mutation or installation. |
| Catalog plans | `crates/vosu-core/src/catalog/plans/` | Immutable resolved entries and exact review fields, T0 artifact approvals, shared state-schema D8 predicate, 64-plan/ten-minute lazy registry, fingerprint/generation checks and single-use catalog-operation ownership. I0 owns bounded worker cancellation/join and prepare-all transaction execution; no install on plan creation. `MAX_PACKAGE_MIB` config/settings supplies one checked solver/download cap. |
| Catalog installation | `crates/vosu-core/src/catalog/install/` | P0 `CatalogExecutor` worker: public-only credential-free `PackageTransport` (production `StreamingClient::download_atomic`), same-handle size/SHA-256, `vosu-net` staged ZIP preflight under each kind root, confined asset reads through the SDK's `manifest::files` rule and SDK `compare_package` with compiled schemas, SDK action-schema compilation and `SettingsSchema::parse`, plugin target library / tool UI / overlay index checks — the same calls `vosu-package-check` makes. Journaled no-replace directory renames and `catalog-installed.json` (generation = commit point) with roll-back/roll-forward recovery in `InstalledStore::open` and at each operation start. Post-commit `RuntimeHandoff` under current T0 policy; process plugins report M5-required. |
| Catalog installed graph and removal | `crates/vosu-core/src/catalog/installed/` | Installed provider graph rebuilt from I0 records and confined current manifests using R0's selected-provider rule (no stored reference counts); pure removal closure with named required-dependent refusal, dropped optional grants and recursive dependency-only autoremove; `UninstallService` facade for H0 under P0's operation gate (synchronous refusals, `CatalogOperation::track_job` polling job), `RemovalRuntime` stop/notify/explicit-data seam, removal commit through I0's journal and recovery; explicit dependency promotion. No routes, no data/settings paths. |
| Catalog composition | `crates/vosu-core/src/catalog/runtime/`, `src/runtime/catalog.rs` | M6b K0: the single daemon-lifetime `CatalogRuntime` H0 consumes. Opens `CatalogFetchService` (S0/C0 reconcile) and `InstalledStore` (I0 recovery) before discovery/routes, wires the executor with the current-policy adapter and daemon-lifetime pending-restart markers, registers G0 as the discovery observer and refreshes it after every source publication/mutation and installed change with the P0-pinned installed generation. Trust-lowering source changes publish T0-cleared approvals durably before the S0 change. Corrupt stores disable their feature untouched. The root owns the install roots (`<data>/catalog`, plugin trees in `<data>/catalog/plugins`, tools in the legacy tool host's `<data>/tools` root, overlays in the startup static folder) and the in-process `dlopen` + `create_instance` / legacy web-host rescan handoff until M7. No new module or crate edge. |
| Catalog sources | `crates/vosu-core/src/catalog/sources/` | Exact-identity settings and journaled lifecycle; event-driven origin-pinned unauthenticated forge detection (16 KiB/probe, five seconds each); lifetime success/failure retry cache; generation-checked immutable candidate snapshots using the SDK whole-source registration context. Failed/disabled sources contribute no candidates. |
| Catalog forge retrieval | `crates/vosu-core/src/catalog/forges/` | Bounded release models, typed metadata Accept, exact unambiguous catalog assets and initial derived-origin checks. `CatalogFetchService::open(config_root)` must run at root startup/recovery before exposing credential/fetch services; its lifecycle adapter reconciles C0 through S0 recovery. The service serializes credential mutations against fetch leases and feeds raw catalogs into S0's single SDK ingestion/publication path. No package credentials, global authenticated client, or real-CA evidence claim. |
| Offline packaging schemas | `docs/v2/schemas/{manifest,catalog-v2}.schema.json`, `tests/sdk/packaging_schema.rs` | Self-contained Draft 2020-12 structural checks and TOML-to-JSON/SDK parity corpus; `jsonschema` is a root dev dependency only (S0 moved the corpus out of the published SDK package). Semantic/context/asset validation remains SDK-owned. |
| Surface plugin API | `crates/vosu-surface/`, `crates/vosu-core/src/plugin/host/surface/routes.rs` | Permanent bundled route/feed registration, coherent captures, granted subscriptions and opaque file/resource operations. No typed game snapshot or global snapshot hook. |
| Bundled root/resource bytes | `crates/vosu-surface/src/{files,resources}.rs`, `crates/vosu-core/src/plugin/host/resources/{surface,surface_files}.rs`, `crates/vosu-core/src/resource_io/surface.rs` | Instance-bound requesters revalidate captured game/session occurrences, retain declared-root epochs, page retained-directory names/metadata and read same-open-object bytes. Calculation-only absolute spellings select the most-specific declared root; resource readers require both live session membership and field/resource grants, reuse M3 resolution/stream leases and cap chart input at 64 MiB. Native cursor enumeration lives in `vosu-sys/src/fs/directory.rs`; no root path or OS handle crosses surface. |
| Host-only diagnostics | `crates/vosu-core/src/plugin/host/{diagnostics,resources}.rs` | Dashboard/report session metadata comes from the host and selected adapter facts. M7 T0 deleted the old tool `/context` contract with its two `tool_context` sources and `PluginHost::display_path` (A7 legacy deletion inventory); tools read API v1 state and resources instead. |
| M7 host destinations (A7 contract) | `crates/vosu-{dashboard,overlay-host,tool-host}/` (D0, O0, T0); core's side in `src/server/`, `src/runtime/{dashboard,overlay_root,service}.rs` and `src/tools/` | The [A7 freeze](../v2/implementation-plan.md#a7-approved-contract-freeze-2026-11-24) maps every current route, provider, asset and management operation to core or to one of the three bundled hosts. Hosts depend only on `vosu-surface`, `vosu-plugin-api` and `vosu-plugin-internal` (plus `vosu-net` for the overlay host). Core keeps every privileged handler, the tool registry with launch authority, and the dashboard-off switch. |
| Overlay host | `crates/vosu-overlay-host/`, `crates/vosu-core/src/plugin/host/resources/overlay_root.rs`, `src/runtime/overlay_root.rs` | The bundled `vosu.overlayhost` (A7.1, A7.1-OR), required at `BUNDLED` index 5: discovery (manifest-first, SDK `manifest::legacy_metadata` for 1.x metadata), the community catalog and cards, download/update/delete through `vosu-net`'s hardened ZIP and publish primitives, names and aliases, settings and profiles, `CommandProcessor` and the preview colour scheme. `OverlayRoutes` registers the counter API (dashboard role: search, details, updates, names, download, delete; both roles: settings, profiles) and the overlay-role `/websocket/commands` feed, whose framing stays in core's hub. Core admits each request (keys, broker, dashboard provenance and CSRF) and passes a `ManagementProvenance` witness for dashboard mutations; opening folders stays in core (`src/server/overlay_folders.rs`). `OverlayStatic` serves overlay files, alias redirects and `COUNTER_PATH` only through the core-minted read-only `RootLease` (`PluginHost::overlay_root_lease`): a top-level directory link is a confined mount, deeper links are never followed, and retiring a generation ends reads of open files. `OverlayRootComposition` seeds `static_folder_path` from `STATIC_FOLDER_PATH`, delivers `SETTINGS_CHANGED` and mints the next lease on each root change. `query.rs` answers the sessionless, plugin-only `vosu.overlayhost.overlays.query` action from one worker thread; composition binds its counter service to the instance's `data_dir` (`bind_overlay_query`), the only link between the vtable instance and the overlay storage. |
| Web tool host | `crates/vosu-tool-host/` | The bundled `vosu.toolhost` (A7.1/A7.2), required at `BUNDLED` index 6. `ToolHost::mount` registers exact overlay `GET` routes for the v2 bridge, theme and design page, plus one `GET`/`HEAD` `/tools/<id>` prefix per tool in the latest core-pushed `ToolHostView` (`vosu-surface::tool_view`), reconciled as views change. It serves static UI through each view's `RootLease`, art with a sandbox CSP in every state, the password-filtered `_settings`, a 302 for `/tools/<id>`, 503 when the tool is not servable and an explicit 404 for `api/*`. A directory request serves its `index.html`. It never mints or checks a session. `mount_design_system` registers the design-system set (`/assets/<design-set>`, `/favicon.ico`) on both listener roles, or the overlay role only while the dashboard is off; core embeds none of it, routes those paths to the request's listener role and adds only the `x-vosu-identity` header to a 200 favicon for the second-launch probe. |
| Bundled plugins | `src/plugins.rs` | The explicit `BUNDLED` array (D13): required `vosu.osu`, `vosu.adapter.upstream`, `vosu.adapter.gosumemory`, `vosu.adapter.streamcompanion`, `vosu.dashboard` (registered even when the dashboard is off), `vosu.overlayhost` and `vosu.toolhost`, then optional fixtures. Each entry embeds its own manifest and SDK vtable; `src/runtime/dev_plugins.rs` owns SDK validation and instance creation. |
| Native access | `crates/vosu-sys/` | Linux/Windows process handles and native `ProcessMemory` backends, signature region walk and module tables, paths, OS behavior, and process-exit-event backends; all platform `unsafe` lives here |
| Process creation | `crates/vosu-sys/src/process_spawn.rs` | The one way the daemon creates child processes: gated `spawn`/`output`/`status` for std and tokio commands and the `open` launchers (`clippy.toml` disallows the direct calls). On Windows one process-wide gate covers each creation, and a plugin-host spawn (`plugin_process/windows/spawn.rs`) holds it while its ring duplicates are inheritable (plugin-abi.md §7.4). ## Cleanup module boundaries

Maintained code files stay at or below 1,000 physical lines, including tests,
benchmarks, dashboard styles/scripts, and maintainer tools. Lockfiles and pinned
JSON/beatmap evidence are data, not source-size exceptions or splitting targets.
`python scripts/check-file-length.py` enforces this in CI. Files that were already
over the limit are listed in `scripts/file-length-baseline.txt`; an entry may
only shrink or be removed (`--update` refuses to raise or add one).

The crate checker independently rejects a revived game-plugin surface edge,
production adapter dependencies on core/game/reader/state/sys, and impure wire
support, even if a broad dependency rule lists the edge. Test-only host/producer
ingress remains allowed.

Dependencies between each crate's own top-level modules are recorded per
crate in `scripts/module-boundaries/<crate>.txt` and checked by
`python scripts/check-module-boundaries.py`; the allowed dependency edges
between workspace crates are recorded in `scripts/crate-boundaries.txt` and
checked by `python scripts/check-crate-boundaries.py` against `cargo
metadata`. Adding either kind of edge is a deliberate change: record it in
the same change that explains the new dependency here or in the
[architecture overview](overview.md). `memory`, `calculation`, and `state`
no longer cycle: the JS-compatible rounding/mods/grade helpers
(`crates/vosu-osu-model/src/root/{helpers,mods,scores}.rs`) and the state reducer's
calculation backend (`crates/vosu-osu-state/src/state_backend.rs`) live under
`vosu-osu-model` and `vosu-osu-state` respectively, not `vosu-osu-calc`, so readers
depend only on the model and `vosu-osu-state -> vosu-osu-calc` (a `scripts/crate-boundaries.txt`
crate edge, not a `scripts/module-boundaries/<crate>.txt` module edge, since `state` is no longer a top-level
module of the `vosu` package) is the only edge left.
The pure `LiveBeatmapEngine` implementation is shared from
`vosu-osu-calc::live_beatmap`; state owns only calculation orchestration, so
chart-resource consumers need no state-reducer dependency.
`server` and `tools` no longer cycle either: `server::service::ToolRegistryRoutes`
(implemented by `tools::ToolRegistry`) covers the exact launch-session exchange
and the dashboard tool management routes, and `server::ids::valid_id`
is the shared identifier check, so `tools -> server` is the only edge left.

- `crates/vosu-osu-reader/src/offset_generator.rs` depends on its own crate's
  `assets` (the embedded generator bundle and offsets template) and `memory`
  (`lazer_loader`'s `OffsetGenerator` trait it implements, `lazer_version`'s
  version check) module edges, recorded in
  `scripts/module-boundaries/vosu-osu-reader.txt`; no other module reaches it.
- `crates/vosu-osu-state/src/bundle/publication.rs` owns immutable snapshot materialization and
  regular/precise Arc reuse; `reducer.rs` owns state transitions.
- `crates/vosu-osu-state/src/bundle/resources.rs` exposes explicit cold resource facts,
  retaining the reader's shared lazer set and skin indexes. Accepted selections advance
  a generation; asynchronous results must pass `ColdResourceFacts::is_current` before
  publication (including instance/reset and root/skin checks). No capture tick constructs
  this descriptor, reads more client memory, or allocates/copies a set index. These are
  internal source facts, not filesystem authority or added public state paths.
- `crates/vosu-osu/src/actions/import/` owns bounded local `.osz` snapshots,
  reusing `vosu-net` counter ZIP count/path/type preflight protections. It prepares
  same-filesystem stable no-clobber stages and selected-context lazer handoffs,
  never writable action destinations or database writes. The dispatch owner
  bounds blocking-worker admission, cancels/joins preparation, retains the
  selected session generation and awaits/reaps handoffs through shutdown.
- `crates/vosu-pp/src/beatmap/random.rs` owns deterministic random-map transforms.
  Calculator tests group gradual, hit-window, mod, stateful-oracle, and scoring
  contracts under their existing integration-test entrypoints.
- Counter settings, v2 hit windows, pause transitions, and updater handoff tests
  live in child modules of their existing suites, sharing the existing fixtures.
- `examples/support/process_event_metrics.rs` owns resource and latency reporting,
  separate from the benchmark's process lifecycle orchestration.
- `tools/oracle/calculator/` separates binding helpers, provenance/coverage
  validation, replay contracts, and pinned multiplier/conversion evidence.
- `tools/input-validation/capture.py` owns bounded WebSocket transport and capture
  accounting; `input_validation.py` owns input playback and live scheduling.
  Both use `validation_error.py` for the shared error contract.
- Offset-generator partial classes separate runtime validation, target ownership,
  and generation; offset-target files separate assembly loading, schema, and CLI
  parsing. Their `bin/` and `obj/` trees are reproducible ignored build output.
  The prepared platform ZIP and checksum are release build inputs, while package
  locks remain maintained inputs.
- The dashboard loads `homepage.js` as an ES module, after the classic
  `theme-init.js`, which applies the stored colour mode before first paint. `tokens.css` is the single
  source of design tokens and `@font-face` rules (custom properties and font
  rules only, with absolute `/assets/` URLs); `system.css` holds the shared
  `v-` components. Tool UIs receive both, concatenated, as
  `/tools/_host/v1/theme.css`, and `design.html` is the reference page at
  `/tools/_host/v1/design` ([design guide](../tools/design.md)). `homepage-settings.js` owns the overlay and tool
  settings editor; `dashboard-tools.js` owns the Tools page and loads only
  there, and mounts `dashboard-plugins.js` (with its own
  `dashboard-plugins.css`), the Plugins section with the approval prompt;
  `homepage-controls.css` follows the base stylesheet and preserves
  settings/dialog/responsive cascade order.

## Workspace boundaries

`Cargo.toml` defines one workspace with the production `vosu` package, the `vosu-sys` crate (native process/platform/process-event boundary, M0 crate split), the `vosu-net` crate (hardened outbound HTTPS streaming and archive extraction, M0 crate split), the `vosu-osu-model` crate (osu! value types and calculation root helpers, M0 crate split), the `vosu-osu-calc` crate (beatmap parsing, progressive state, and legacy/live calculation engines over `vosu-pp`, M0 crate split), the `vosu-osu-reader` crate (stable/lazer memory readers and offsets, the pointer-width managed-heap read layer, and osu!-specific discovery inputs, M0 crate split), the `vosu-osu-state` crate (reducer, capture scheduling, and gameplay state, plus the state calculation backend, M0 crate split), the `vosu-pp` facade plus its `rosu-map-api` and `rosu-pp-api` members, the integration-only `vosu-test-harness`, the dependency-isolated `vosu-release-smoke` package, and the dev-only `vosu-proptest` package (`vosu_proptest_config()`, shared by every `prop_*` test). The smoke package launches an external packaged executable and does not depend on the daemon crate. Release profiles retain thin LTO, one codegen unit, stripped symbols, and abort-on-panic; `test-harness` is rejected by `build.rs` in release builds.
